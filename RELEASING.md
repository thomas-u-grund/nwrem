# Releasing nwrem

## Master procedure: https://github.com/thomas-u-grund/nwcommands/blob/main/RELEASING.md

All release procedures and policies of the five packages (steps, order, test launch, tags, GitHub release, website update, Zenodo, lockstep with the core
Mata library, building libraries with Stata 17, known traps) are in the master document above. Follow it; this file only holds what is specific to nwrem.
Two rules from there that are easy to miss: push the release tag by name (`git push origin vX.Y.Z`), never `git push origin main --tags`
(old local tags of this clone never existed on GitHub); and build `lib/*.mlib` with Stata 17, not 18.

## Version files and checks

- Single source of truth: `VERSION` (line 1 the version, line 2 the release date in Stata format, e.g. `25oct2026`). Semantic versioning (master B.4, C4).
- `python3 tools/set_version.py X.Y.Z [date]` writes it into every display (first line of every `.ado`, help headers and the footer of every help file, `nwrem.pkg`, `stata.toc`,
  `README.md`, `NOTICE.md`, `CITATION.cff`, the `e(version)` / `nwrem version` literals); `--check` changes nothing.
- Add `## [X.Y.Z] - YYYY-MM-DD` to `CHANGELOG.md` (Added / Changed / Fixed / Removed); its text is the GitHub release notes.
- `NWCORE=/path/to/nwcommands python3 tools/check_version.py` = version check plus the core-library hash check (below).
- Install lines: latest `net install nwrem, from(https://raw.githubusercontent.com/thomas-u-grund/nwrem/main/) replace`; a given release `.../nwrem/vX.Y.Z/`.
  `nwrem.pkg` states `Requires nwcommands (core), version A.B.C or later`; raise it (and `README.md`) only when this release needs a newer core.

## Library and lockstep with the core

`lib/build.do` builds `lib/lnwrem.mlib` from `unw_rem.do`; it does not load the core and the sources do not mention `nw_def` (verified 2026-10-25). The package still carries `lib/core_mlib.sha256` and `check_version.py` fails when it differs from `$NWCORE/lib/lnwcommands.mlib`.
In a lockstep batch (master C3): rebuild with Stata 17 (`<Stata 17> -e do lib/build.do` from the repository root), `NWCORE=/path/to/nwcommands python3 tools/record_core_lib.py`, test, patch release. Whether a record-only update is enough is an open decision (master B.5).
- `nwinstall, buildmata(nwrem)` (core `nwinstall_buildmata.ado`) rebuilds lnwrem.mlib on the user's computer from `unw_rem.do` on `main`. A new or renamed Mata source file or library of this package must be added to `nwinstall_buildmata_tab` in the core (see its GOTCHA.md), and the `mata mlib add` patterns there must match `lib/build.do`.

## Tests

`NWCORE=/path/to/nwcommands cscripts/run_tests.sh [jobs]` (first step: `tools/check_version.py`; each test runs in its own `-e` Stata process; set `STATA` to the Stata 17 binary, then repeat with 18).
Most tests print no PASS marker: failure is an `r()` error and a missing log is NOT RUN (master C0).

## Plugin

`native/rem_sim.c` builds `rem_sim` (likelihood, gradient and exact Hessian of all 27 effects, ordinal and interval likelihood, risk sets); `.github/workflows/build-plugins.yml` builds the macOS, Linux and Windows binaries on a push that touches `native/` and commits them to `lib/plugins/<platform>/` (`pull --rebase` before the next push, tag after the bot commit). Locally `make -C native macos` (Stata is not needed) writes `lib/plugins/macos/rem_sim_macos.plugin`; the Linux and Windows binaries are never committed by hand and are stale on a development machine until CI has run.
Every fit needs the plugin (no Mata fallback): a missing plugin file stops the command with r(601), a plugin that speaks another protocol (or cannot be loaded) with r(3495). The protocol number is `REM_PROTOCOL` in `native/rem_sim.c` and `REM_PROTOCOL_NEEDED()` in `unw_rem.do`; raise both together whenever the blob layout or the meaning of an argument changes, so that an old plugin is recognised instead of giving wrong numbers. A release rebuilds `lib/lnwrem.mlib` with Stata 17 and the three plugins from the same commit: until CI has rebuilt Linux and Windows those platforms stop with r(3495) or r(601).
A stale installed plugin shadows the repo build: scratch `adopath`, `rm` before `cp` (a loaded plugin stays loaded for the rest of the session and macOS kills Stata when a loaded plugin is overwritten).
Plugin protocol 2 (version 1.4.0): a different blob layout (header of 48 cells, mode, conditioning, mask, windows, drop flags). The tests against relevent are `test_nwrem_relevent14.do` and `test_nwrem_collinear14.do` with `cscripts/ref14/` (generated by `dev/rem_relevent14_gen.R`; regenerate only when the cases change; no R is needed to run the tests). The Mata evaluators of the versions up to 1.2.0 are test-only reference code (`cscripts/ref_rem_mata.do`); `test_nwrem_plugin.do` compares the plugin with them (every effect, every pair, random subsets, all 16,383 subsets, ties, repeated dyads, valued covevent, extreme coefficients, the dependence check). `test_nwrem_noplugin.do` and `test_nwrem_oldplugin.do` are separate files because a plugin stays loaded.
Core: `nwinstall, buildplugin(nwrem)` exists since core 3.26.0; version 1.4.0 needs no further core change.

## Manual

The manual is in `manual/` (see `manual/README.md`); the PDF is on the website and on Zenodo (all-versions DOI 10.5281/zenodo.24398012). Rebuild and re-label it (`\manualseries`) for a new minor series (master B.10); the owner uploads the PDF as a new file version of the existing record. The model follows Butts (2008), cross-checked with R `relevent` (master B.8).
